# Match Prep

`/events/[eventKey]/match-prep` is restricted to active strategy/admin profiles. It reads cached schedule, team metrics, final 2026 version-2 scouting records, and final pit reports. It makes no live provider calls. With no explicit selection, a configured `events.our_team_number` defaults the page to that team's next upcoming match. Matches with an actual time or posted results are excluded from this automatic selection.

The Select match control includes all cached event matches, grouped into Qualifications and Playoffs using the shared official labels. Posted nonnegative alliance scores mark a match Completed; an actual time without posted results is labeled Started · result pending. The selector remains available when no upcoming match exists, including completed events. No cached schedule produces instructions to sync it under Admin Events.

Explicit selection uses `/events/[eventKey]/match-prep?match=<canonical TBA match key>`. Native GET navigation supports refresh, sharing and back/forward. Match Details links directly to this URL. A key absent from the current event redirects to its base Match Prep URL, safely clearing stale selection. Event schedule pagination reads all cached matches and stations within the existing 20,000-row safety bound.

Schedule, Match Details and Match Prep use `src/features/events/match-stations.ts` to preserve R1/R2/R3 then B1/B2/B3. The helper orders only by official alliance and station, preserves associated evidence, and does not invent missing stations. Match Prep displays station labels on the six team cards.

Admin event settings validate the team number against the event roster. The setting is optional and never hard-coded. Without it, Match Prep requires explicit match selection and cannot identify our alliance.

The same renderer and evidence query serve upcoming and historical selections. Cards show event rank, EPA, available TBA FUEL COPR, pit specifications and strategy notes, observed role distribution, confident usable median FUEL with its sample size, observed auto success, timed passing share, defense frequency, and reliability. Missing internal scouting remains explicitly unavailable even when external metrics exist. Pit weight excludes battery and bumpers. Very-uncertain recent FUEL observations are called out and excluded from the median. Expected behavior phrases follow fixed thresholds in `src/features/match-prep/model.ts`; no generated strategy is used. Summaries reflect the current event cache, rather than an as-of-match snapshot.

Auto compatibility lists each ally's pit-claimed start sides and match-observed auto success separately. Shared known start sides trigger a possible overlap warning. Pit data has no route geometry, so the page does not infer path collisions. Strategy/admin users can save one concise plan per match. Row-level security allows strategy/admin reading and active-event writing; archived events are read-only.

Existing migration: `20261004000000_match_prep.sql`. The selection and station-helper additions require no new migration or environment variables. Unit/query/UI tests cover automatic and explicit selection, completed-event browsing, invalid keys across events, cache pagination, exact station order, missing internal scouting, canonical URL reloads, Match Details navigation, role ties, FUEL uncertainty, and shared start sides. The existing SQL test covers role and archive boundaries. No demonstration match, plan, or scouting submission is added to an event.
