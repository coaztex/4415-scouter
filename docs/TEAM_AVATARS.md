# Team avatars

Team branding and robot photos are separate event media. The TBA event media adapter reads designated `avatar` entries and their `details.base64Image` payloads on an admin event sync. It validates the encoded image and decodes it with Sharp, trims uniform outer canvas padding, and fits the complete artwork inside a 48 px square. PNG-style artwork uses nearest-neighbor resizing to keep hard edges; JPEG artwork uses smooth resizing. Lossless WebP avoids an additional compression blur. The original TBA avatars are generally only 40 px, so the cache cannot invent fine detail. `team_avatars` stores the event/team path and TBA source. Other TBA image types remain robot-photo candidates and never become avatars. No client calls TBA.

The Teams directory and Team page request one batch of one-hour signed URLs for cached avatars. Directory images load lazily from the 48 px cached copy in fixed 48 px boxes; the Team header also uses 48 px. Wide or tall logos retain their proportions and may have space inside the square rather than lose text or artwork. If no avatar exists or the image fails to load, a fixed-size team-number mark appears. Logos are decorative beside the explicit team name and have no descriptive caption. The Team overview still shows its separate large pit robot photo, then a TBA robot image, then a placeholder.

The existing app has no local team-branding upload workflow, so no local branding source is selected. Adding one later should be explicit and should not reuse pit robot photos. Admin sync retains previously cached avatars if the provider omits them or fails. The cache refreshes when admin sync runs.
