# Event Teams module

`/events/[eventKey]/teams` reads the event roster, rankings, cached TBA/Statbotics metrics, final version-2 match submissions, and match identities in a fixed set of batched Supabase queries. It never calls an external provider or performs a request per team. Typical FRC event rosters render without pagination.

The directory stores search, sort direction, pit filter, and selected metric in URL query parameters. Missing values display as `—` and sort after known values in both directions; observed zero remains a real value. The default card stays compact with team identity, pit status, most common observed role, Statbotics EPA, confident median FUEL, and full-match rate. Choosing another sort adds one contextual value without expanding every card into a full metrics table.

All human metrics come from `src/games/2026-rebuilt/aggregate.ts`. One deterministic latest final is selected per event/match/team before aggregation to prevent duplicate observations from inflating a team. Invalid or non-version-2 payloads do not enter current-season analytics. Very-uncertain and DNS/DNF FUEL remains visible on the match record but is excluded from default FUEL summaries. The UI displays total scouted matches and the smaller confident-FUEL denominator when they differ. A real zero from a completed match remains included; an entirely unknown/uncertain sample displays `—`.

Team detail contains Overview, Matches, Pit, Notes, Incidents, and Media sections. External provider estimates and official-derived TBA components are visually separated from human observations. A neutral **Worth reviewing** marker appears when human mean total FUEL and TBA total FUEL COPR are both present and differ by at least 10 FUEL or 50% of the external value. It does not alter either source or create a combined score. Statbotics EPA is shown alongside the other sources but is labeled as a model points estimate and is not directly compared to human FUEL counts.

The robot profile includes observed roles, confident FUEL, scoring and shuttling/passing activity, defense, AUTO success with a two-match minimum, reliability, and subjective driver-control support. Pit traversal and shoot-while-moving are explicitly labeled as pit-reported claims. Climb stays secondary. `Cycler` is not a role.

Matches link to read-only validated records. RLS decides which submissions each user can read: strategy/admin see all active-event submissions; a scout sees their own records under the established policy. Records highlight issues, DNF/DNS, major reliability problems, and very-uncertain estimates. New-schema shuttling/passing activity is used; legacy shuffle count is not presented.

Strategy/admin can add event-specific notes. Migration `20261002000000_strategy_team_notes.sql` narrows note create/update/delete policies to strategy or admin and keeps author ownership for later edits/deletion. All authenticated event viewers may read the shared notes. The current UI only creates notes; editing/deletion is deferred.

The latest readable completed pit record supplies claimed capabilities and autonomous routines. The overview shows the newest available pit robot photo from private Supabase Storage through a one-hour signed URL. If none exists, it uses a validated cached TBA robot image; otherwise it shows a placeholder. Admins can remove incorrect pit uploads from the Media tab; TBA images are managed by provider sync. Team branding avatars appear beside identity in the directory and Team header, separately from robot photos. Existing historical pit photo UUID references remain readable but are not treated as delivered files without a matching media row.

Unit tests cover URL filtering/sorting, null-last behavior, zero values, confident-FUEL filtering, record visibility in analytics, role vocabulary, and duplicate canonicalization. The SQL policy test verifies scout read-only access and strategy note creation. No production fixture data is added.
