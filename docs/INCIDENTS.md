# Incident evidence and reliability

The final version-2 match submission is the scout's original evidence. Scouts record observed status (`normal`, `minor_issue`, `major_issue`, `DNF`, or `DNS`), issue category, optional symptom note and recovery. They do not diagnose a root cause. Match capture rejects `confirmed_cause` in the submitted JSON, and its server RPC enforces this even if a client bypasses the form.

`team_incidents` projects each observed issue from an accepted final submission. A non-normal status without an issue event creates one status-only incident. The projection runs in the same database transaction as final submission, so a failed projection cannot leave an accepted submission without its review record. Existing final version-2 submissions were backfilled when the migration applied. The `(submission, observation_key)` constraint makes replay idempotent. The projection does not create individual rows for taps or activity transitions.

The incident's observation columns and source submission ID are immutable. A strategy or admin reviewer can add one later cause through the Incident Review page, with `team_confirmed`, `strategy_confirmed`, or another documented evidence source, an evidence note, reviewer ID and timestamp. The narrow service-role RPC checks the reviewer's active profile and refuses a second confirmation. A correction to a confirmed cause needs a deliberate future audit workflow, rather than overwriting evidence. Database clients have read-only table privileges; RLS lets active-event strategy/admin users read all incidents and scouts read only those derived from their own submissions. Archived events remain admin-only.

Team detail shows full-match rate with its sample size and a chronological incident list. Scout observations and later confirmation appear in separate columns. A recent major issue, DNF, or DNS among the last three scouted matches produces a small team-page flag. Future match prep can reuse `recentReliabilityFlag` in `src/features/incidents/model.ts` without inferring a cause.

Availability and offense have distinct denominators. DNS and DNF count in reliability/full-match rate. Their partial or absent FUEL values remain on the original match record, but default FUEL aggregates exclude those matches. Very-uncertain FUEL is also excluded by default. A genuine zero from a completed match remains zero.
