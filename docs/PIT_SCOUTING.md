# 2026 pit scouting

From the event home, open Pit Scouting. The list searches event teams by number or nickname, puts unscouted teams first, shows current status and completed progress, and filters to All, Unscouted, or Completed. The team form records pit claims and demonstrations; match observations remain a separate data source. This is the version-2 `2026-rebuilt` pit schema, and the server parses it before saving.

Choose an approximate numeric FUEL capacity when the team knows it. Zero is valid. Otherwise choose Unknown or a low/medium/high qualitative fallback. Add only autonomous routines the team can describe. The Robot photo card accepts camera or file input for up to four event/team images. Photos are uploaded separately from the text report, including after final submission. Offline photos can be selected again later; text scouting continues through the normal device queue. The server validates and resizes images to at most 1600 px and 2 MB before private Storage upload. A field-relative point/vector route sketch may be added later; no drawing canvas or raster route is stored now.

Robot weight is a pit-reported value in pounds for the robot **without battery or bumpers**. It accepts positive integers or decimals; blank means unknown and is saved as null, never zero. The optional `robot_weight_lbs` field remains in the version-2 game payload. Older reports and drafts without it read as unknown, so no database migration or schema-version increment is needed. The team profile displays the value with its pit-reported context, and the team directory exposes it to Picklist without reading raw JSON there.

**Primary scoring mechanism** is a compact, event-specific 2026 pit classification: Drum, Turret, Other, or Unknown. Unknown is selected until a scout records a mechanism. Other requires a short shooter-type description on final submission; an unfinished Other answer can remain in a device draft. The field is part of the 2026 game payload, not the timeless team record. Older final reports and drafts without it parse as Unknown. The existing JSON storage needs no database migration or schema-version bump because the parser supplies that default. Team pages label the badge as pit information and show Not yet pit reported when no completed report exists.

Opening an unscouted team does not claim it. **Begin pit report** creates a visible claim. If another scout has a claim, the form requires a checked takeover statement and confirmation before transfer. Their draft remains separate. Save draft reuses one client submission UUID and checks its revision. A stale draft, lost claim, completed report, or closed event fails safely without overwriting another report. Submit marks the report final and the event-team status completed in one locked PostgreSQL transaction. Retrying the same final UUID and identical payload returns the original result. Completed reports are read-only in this flow; corrections require a later explicit review workflow.

The server action checks the signed-in active profile and parses the game payload. A service-role-only RPC performs the claim and save transaction. The service key stays server-only. Ordinary authenticated clients can read their own drafts and submissions; strategy/admin can read all submissions under RLS. Direct authenticated pit-submission writes and event-team updates are revoked. No new environment variables are needed beyond the existing Supabase service key.

Draft edits and Save draft now persist in IndexedDB on the current device. Final Submit validates and queues the report before attempting the server transaction. Offline captures never take another scout's claim automatically; a changed claim stops sync for review. See [offline scouting](OFFLINE_SCOUTING.md) for retries, storage recovery, confirmations, and current page-loading limits.

Optional Nexus synchronization now exposes cached pit addresses on team cards and forms. Scouting page loads never call Nexus, and unavailable maps do not affect submissions. See [event pit maps](PIT_MAPS.md) for the additive migration, optional server key, admin refresh and normalized layout contract.

Run `npm test`, `npm run test:ui`, `npm run lint`, `npm run typecheck`, and `npm run build` for application checks. SQL behavior is tested with `tests/sql/pit-capture.sql` in a disposable PostgreSQL database after the Auth fixture and migrations; never apply the fixture to a real Supabase project.
